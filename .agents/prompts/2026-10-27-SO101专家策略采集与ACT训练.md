## 关键发现（省掉重写运动学）

1. **环境原生支持末端位姿控制**：`control_mode="pd_ee_pose"` → action 是 **7 维绝对位姿** `[x, y, z, wx, wy, wz, gripper]`（米 + 世界系旋转向量 + 归一化夹爪）。环境内部用 `_solve_ee_ik`（阻尼最小二乘，`ee_ik_delta_q`，每步迭代 `EE_IK_ITERATIONS=3`）解 IK 成 6 个关节目标。**不要自己写 IK 循环**。
2. **SimSOFollower 支持 EE 模式**：`SimSOFollowerConfig(env_kwargs={"control_mode": "pd_ee_pose", "render_mode": "rgb_array"})` 时，`action_features` 自动变成 LeRobot 的 `ee.x/ee.y/ee.z/ee.wx/ee.wy/ee.wz/ee.gripper_pos`（定义在 `lerobot_adapter/sim_follower.py` 的 `EE_ACTION_KEYS`）。delta 模式会被拒绝，绝对模式才允许。
3. **成功判据现成**：`env.step()` 的 info 里有 `success`（PickLift = `lift_height > lift_threshold(默认0.05m)` 且 `is_grasped > 0.5`），还有 `is_grasped`、`lift_height`、`tcp_to_obj_dist`、`target_index`。用它筛 episode、做 rollout 验收。
4. **环境内部可直接读位姿**（同进程，写采集脚本时可用）：`env.unwrapped._get_tcp_pose()` → `[x,y,z,qw,qx,qy,qz]`；`_get_target_pose()` → 目标物位姿。`env.unwrapped.control_mode` 可确认模式。
5. 观测：smoke 数据集 schema 是 `observation.state` 6 维（关节，motor 单位）+ `observation.images.laptop` 640×480 视频 + `action` 6 维。EE 模式下 action 会变 7 维，这是预期变化，ACT 会按 meta 自动推断维度。

## 任务（按顺序做，每步有验收）

### 1. 写专家策略 + 采集脚本 `G:\SO-ARM100\so101-sim\expert_collect.py`

状态机（笛卡尔路点，目标物位置每 episode 从 env 读，不要硬编码）：
1. **悬停**：目标物正上方 ~0.08m，姿态用初始 TCP 四元数（保持向下）
2. **下探**：降到抓取高度（贴近物块中心，按物块尺寸留 1~2mm）
3. **闭合夹爪**：`ee.gripper_pos` 从张开值渐变到闭合值（分 5~8 帧，别瞬间闭合）
4. **提升**：+0.10m，保持 5~10 帧
5. **判定**：`info["is_grasped"] > 0.5` 且最终 `info["success"]` 为真才算成功

实现建议（读源码确认细节再写）：
- `so101_nexus/lerobot_adapter/sim_follower.py`：`send_action` 收的 dict key、`get_observation` 返回结构、`_last_step_info`
- `so101_nexus/mujoco/base_env.py`：`_solve_ee_ik`、`_get_tcp_pose`、`_action_to_ctrl`
- `so101_nexus/mujoco/pick_env.py`：`_get_info`（success 等字段）、`_get_target_pose`

采集：**自己写循环 + `LeRobotDataset.create(...)`**（比 record 管道更好控，能按 success 过滤）：
- `features` 照抄 `/mnt/g/SO-ARM100/so101-sim/datasets/meta/info.json`（把 action 改 7 维、names 用 `ee.*`）
- 每帧 `add_frame({...obs, **action, "task": "PickLift"})`，成功后 `save_episode()`；失败则丢弃不落盘
- 目标 **25 条成功 episode**，30fps，单条 3~5 秒（90~150 帧）；总帧数 ~3000
- 数据落 `/mnt/g/SO-ARM100/so101-sim/datasets_expert`（repo_id 如 `local/sim_picklift_expert`）
- 若 `LeRobotDataset.create` 在 0.6.2 的签名对不上，直接读 `lerobot/datasets/lerobot_dataset.py` 确认，不要猜
- 备份方案：实在绕不过就退回 `record()` + 自定义 `Teleoperator`（注册 `register_subclass("ee_expert")`，返回 `ee.*` dict），录完用 info 逐条筛

**验收**：脚本打印每条 episode 的 `success/is_grasped/lift_height/frames`，25 条全 success；抽查一条数据集的视频帧能看出「下探-抓住-抬起」。

### 2. 训练 ACT `G:\SO-ARM100\so101-sim\train_act_expert.py`

从 `G:\SO-ARM100\so101-sim\train_act_smoke.py` 改（它的坑都已趟平）：
- `dataset.repo_id` → 新数据集；`output_dir=Path("/mnt/g/SO-ARM100/so101-sim/act_expert_out")`
- `ACTConfig(chunk_size=50, n_action_steps=25, device="cuda", push_to_hub=False)`
- `batch_size=8`，`steps=4000`（25 条数据、4G 显存，先跑 4000 看 loss；不够再加）
- 后台跑 `terminal(background=true, notify=true)`，日志只 grep `step.*loss` 和显存
- **每 500 步看显存**：>3.8G 就降 batch 或 chunk

**验收**：训练跑完，checkpoint 落 `/mnt/g/SO-ARM100/so101-sim/act_expert_out/checkpoints/<step>/pretrained_model/model.safetensors`；loss 曲线下降（但**loss 不是验收标准**）。

### 3. Rollout 验证 `G:\SO-ARM100\so101-sim\eval_act_expert.py`

- 加载 checkpoint 的 policy，在同一环境跑 **20 个 episode**（不同 seed）
- 每步：policy 预测 action → 环境 step；记录 `info["success"]`、抓住步数、是否抬起
- 打印成功率；失败 episode 记录卡在哪一阶段（没碰到/没抓住/没抬起）

**验收（唯一标准）**：20 次 rollout 成功率 ≥ 60% 才能说任务完成；低于就问用户要不要加数据/调参，不要用 loss 好看代替成功率。
